# 11팀 자가개선 증거 판정 기준

작성 2026-10-16. 코드 정본: `scripts/build_team_baselines.py`(측정), `scripts/team_improvement_evidence.py`(판정).
대시보드 「11팀 자가개선 증거」 표의 각 칸이 무엇을 뜻하는지, 무엇을 하면 바뀌는지를 적는다.

## 1. 공통 원칙

모든 팀에 같은 다섯 가지를 적용한다. CLAUDE.md 「"최고" 를 숫자로 바꾼다」 세 줄을 칸으로 옮긴 것이다.

| # | 질문 | 판정에 쓰는 값 | 통과 조건 |
|---|---|---|---|
| 1 | 무엇을 세나 | 팀 지표 1개 (아래 표) | `data/` 의 실제 산출물에서 센 정수. 추정·수기 입력 불가 |
| 2 | 기준선이 있나 | `baseline` | 처음 잰 값을 고정. 사람이 지우기 전까지 덮어쓰지 않는다 |
| 3 | 근거가 살아 있나 | `source_clock` (근거 파일이 스스로 적은 시각) | 판정 시점에서 **14일 이내** |
| 4 | 비교가 됐나 | `baseline` 과 `current` 의 근거 시각이 다르다 | 같으면 「다음 측정 대기」 |
| 5 | 좋아졌나 | 지표 방향(증가/감소)으로 `current - baseline` | 내부 측정일 뿐 매출·성과 검증(verified_gain)이 아니다 |

`measured_at`(센 시각)은 판정에 쓰지 않는다. 2주 지난 파일을 오늘 세면 오늘 측정처럼 보였기 때문이다(2026-10-16 수정).

## 3. 표의 칸이 뜻하는 것

**실제 개선 단계**

| 표시 | 뜻 | 다음 단계로 가려면 |
|---|---|---|
| 감시만 | 기준선이 있고 근거가 14일 이내다 | 다음 측정에서 값이 지표 방향으로 움직여야 한다 |
| 차단·근거 대기 | 근거 파일이 없거나, 형식이 틀렸거나, 14일을 넘었다 | 그 팀 수집기·생성기가 실제로 다시 돌아 근거 파일 시각이 새로 찍혀야 한다 |
| 제안·자료 대기 | 지표는 정했지만 측정값이 아직 없다 | 첫 측정 |
| 그림자 검증 보고 / 정책 적용 보고 | 예전 시험 결과 (검토된 파일 바이트가 그대로일 때만) | 독립 정답 또는 사업 결과 필요 |

**남은 검증(사유)**

| 표시 | 코드 | 해소 조건 |
|---|---|---|
| 근거 없음 또는 오래됨 | `required_evidence_unavailable_or_stale` / `stale_observation` | 근거 파일 시각이 14일 이내로 새로 찍힘 |
| 다음 측정 대기 | `awaiting_next_measurement` | 기준선과 다른 시각의 측정이 한 번 더 |
| 추가 근거 검토 필요 | `internal_metric_not_business_gain` | 정상 상태. 내부 지표라 매출 성과로는 인정하지 않는다는 표시 |
| 사람 승인 또는 외부 조건 대기 | `approval_or_external_dependency` | 사람 승인 또는 외부 선행조건 해결 |

**기준 > 현재** 칸은 `기준선 값 > 지금 값 / 분모` 다. 값이 없으면 「비교 자료 없음」.

## 4. 하지 않는 것

- 지표가 오르게 지표 정의를 바꾸지 않는다. 지표를 바꾸면 기준선을 새로 잡는다(이전 값과 비교하지 않는다).
- 근거 시각이 없는 값을 신선하다고 보지 않는다.
- 내부 지표의 변화를 「검증된 성과 개선」(verified_gain)으로 올리지 않는다. 그 칸은 사업 결과가 들어올 때까지 0 이다.

## 추가 근거: git 이력 시계열 (2026-10-17)

기준선 1개와 현재값 1개만으로는 "어제보다 나은가" 를 판정하기 어렵다. 현재값은 Core·Deep
자동화가 돌 때만 갱신되는데, 두 자동화가 멈추면 11팀이 모두 같은 숫자로 굳는다.

그래서 같은 측정 함수(`build_team_baselines.measure`)를 날짜별 마지막 커밋의 실제 파일에
적용한 21일 시계열을 근거로 하나 더 둔다.

- 생성: `scripts/team_history_evidence.py` → `data/self_improve/team_history_evidence.json`
  (발행 재생성 때 `generate_dashboard_runtime.py` 가 먼저 갱신한다. 얕은 clone 이면 기존 파일 유지)
- 판정 (7일 전·하루 전 대비)
  - `improved` / `same` / `worse` : 지표 방향(increase/decrease)에 맞춘 비교
  - `source_not_refreshed` : 두 시점 근거 파일 시각이 같다. 값이 같아도 '개선 없음' 이 아니라 '다시 재지 않음'
  - `not_comparable` : 분모(대상 범위)가 한쪽에만 있다
  - 분모가 둘 다 있고 다르면 비율로 판정하고 `denominator_changed` 를 남긴다
  - `insufficient_history` : 비교 시점에 근거 파일이 없었다
- 사람은 커밋 SHA 로 같은 파일을 열어 숫자를 직접 확인할 수 있다.
- 사업 성과 검증이 아니다. 단계(phase)·상태(status)는 바꾸지 않는다.
