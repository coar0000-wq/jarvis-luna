## 이번 최소 적용 범위

1. `expand_obsidian_graph.compile_topic_patterns`와 `topic_names(..., learned_patterns=...)`를 운영과 평가가 공유한다. 평가 중 운영 전역 캐시를 바꾸지 않는다.
2. `scripts/self_improve.py`의 키워드 개수 추산을 실제 운영 분류기 재실행으로 대체한다. 하이픈 경계, 기존 분류와의 충돌, 롤백도 실제 그림자 결과에 반영한다.
3. 평가에 실행 코드, 입력 레코드, 전후 키워드 규칙의 SHA-256을 기록한다. 키워드 규칙 해시는 전체 정책 파일의 바이트 해시가 아니라 해당 규칙 사전의 해시다.
4. 정책/상태/이력/장부 저장은 배타적 파일 잠금, 읽기 당시 원본 해시 비교, 고유 임시 파일의 원자적 교체를 사용한다. 충돌 시 쓰기를 거절하고 다음 실행에서 다시 읽고 평가한다. 이는 파일별 가드이며 여러 파일 전체의 트랜잭션은 아니다.
5. 기존 백그라운드 자기개선 실행에서 `data/self_improve/memory.json`을 만든다. 운영 이력과 롤백 장부만 정리하며 원문 오류, 고객 자료, 비밀 값은 복사하지 않는다.
6. 같은 관찰은 중복 제거하고 오래된 관찰은 현재 문제로 재서술하지 않는다. 14일 창과 반복 관찰 2회 기준은 이번 구현의 보수적 선택이며 영상에서 제시된 숫자가 아니다.
7. 운영 메모리는 근거와 검토 제안만 담는다. 공통 지침, 법률/고시 정본, 상품 공개, 결제, 모델 가중치를 자동 수정하지 않는다.
8. 기존 2시간 자기개선 워크플로를 재사용한다. 별도 중복 스케줄, Weave 계정, Managed Agents/Dreaming 유료 API를 추가하지 않는다.

## 검증

- `python scripts/test_self_improve_replay.py`: 네트워크 없는 회귀 테스트. 운영 분류 재현, 전역 캐시 불변, 하이픈 경계, 롤백, 저장 규칙 해시, 메모리 중복/노후화, 동시 쓰기 거절을 검증한다.
- 샌드박스용 `SELF_IMPROVE_TEST_IO_DIR`을 지정하면 미리 준비된 허용 폴더에서 실제 저장/충돌 검사와 기존 `test_self_improve.py`도 실행한다. 이 환경에서 총 20개 테스트가 통과했다.
- 5,552개 로컬 자료의 `self_improve.py --dry-run`에서 미분류 485 -> 461, 후보 키워드 `cream` 1개를 확인했다. 운영 성과가 아니라 해당 로컬 스냅샷의 그림자 결과다.
- `preflight.yml`에 새 회귀 테스트를 연결했다.

원격 저장소 반영과 CI 확인은 권한 있는 GitHub 계정으로 반영한 뒤 별도로 확인해야 한다. 위 드라이런 수치를 운영 반영 완료로 해석하지 않는다.
