# 맷 포콕(Matt Pocock) AI 코딩 스킬 적용 체크리스트 & 프롬프트 템플릿

이 문서는 깃허브 스타 29만 개 제작자인 맷 포콕(Matt Pocock)의 AI 코딩 스킬과 고품질 개발 워크플로우를 실제 프로젝트에 바로 적용할 수 있도록 정리한 체크리스트 및 프롬프트 템플릿 모음입니다.

---

## 1. AI 코딩 워크플로우 단계별 체크리스트

### 📋 Phase 1: 초기 설정 & 기획 (`greet-with-docs`)
- [ ] **환경 초기화**: 작업할 저장소에서 `setup-pocock-skills` 실행하여 문서 및 할 일(Task) 위치 정립
- [ ] **아이디어 전달**: 구현하려는 핵심 기능 및 목표를 명확히 작성
- [ ] **AI 역질문 답변**: AI가 던지는 질의에 답하며 명세의 빠진 조건과 예외 상황 보완
- [ ] **용어집(Glossary) 작성**: 개발자와 AI 간 동의어 및 개념 차이(예: '취소' = 단건 삭제 vs 주문 전체 취소) 명시
- [ ] **의사결정 기록(Decision Log)**: 주요 기술 선택 및 설계 이유를 문서로 남겨 지속적인 맥락 유지

### 🧪 Phase 2: 구현 및 실시간 검증 (`TDD`)
- [ ] **실패하는 테스트 작성**: 요구사항을 검증하는 테스트 코드를 먼저 작성
- [ ] **테스트 유효성 검증**: 테스트가 먼저 '의도대로 실패'하는지 AI가 직접 실행하여 확인
- [ ] **기능 구현 반복**: 테스트가 통과할 때까지 AI가 코드를 작성 및 수정
- [ ] **시각적/UI 검증 (선택)**: 브라우저/앱 실행 및 스크린샷 캡처를 통한 실시간 동작 확인
- [ ] **추론 강도 최적화**: 테스트 검증 환경 구축 후 AI 추론 강도를 '중간'으로 조정하여 속도 및 비용 최적화

### 🏗️ Phase 3: 구조 유지보수 (`improve-codebase-architecture`)
- [ ] **주기적 구조 분석**: 며칠 단위로 전체 코드베이스 아키텍처 상태 점검 실행
- [ ] **리팩터링 후보 리뷰**: AI가 제안한 결합도/복잡도 개선 보고서 확인
- [ ] **방향성 협의**: 고칠 항목을 선택한 후 질의응답을 거쳐 안전한 개선 방향 확정
- [ ] **구조 개선 진행**: 기존 기능(테스트 통과 상태)을 유지하면서 코드 가독성 및 확장성 확보

## 2. 스킬별 맞춤형 프롬프트 템플릿

### 💬 템플릿 1: 명세 구체화 및 용어집 생성 (`greet-with-docs`)

```text
[역할 정의]
당신은 'greet-with-docs' 스킬을 수행하는 수석 소프트웨어 아키텍트입니다.
개발자인 나의 의도와 당신(AI)의 맥락 이해도를 100% 일치시키는 것이 목표입니다.

[작업 범위]
내가 구현하고자 하는 기능:
"{구현하고자 하는 기능을 상세히 작성하세요. 예: 사용자 프로필 페이지 내 비밀번호 변경 및 OAuth 계정 연동 기능}"

[지시 사항]
1. 기존 코드베이스를 탐색하여 관련된 기존 데이터 구조, API, 컴포넌트를 파악하세요.
2. 내가 당연하게 여겨 언급하지 않은 조건, 예외 케이스, 경계값(Edge cases)을 도출하기 위해 나에게 3~5가지 명확한 질문을 던져주세요.
3. 이 작업에서 쓰일 핵심 용어(e.g., '연동 해제'와 '계정 삭제'의 차이 등)를 정의하는 용어집(Glossary) 항목을 제안하세요.
4. 우리가 나눈 질의응답 결과를 바탕으로 프로젝트 내 `/docs` 또는 지정된 위치에 기획 및 아키텍처 결정 문서를 업데이트하세요.
```

### 🧪 템플릿 2: 테스트 주도 개발 및 실시간 검증 (`TDD`)

```text
[역할 정의]
당신은 'TDD(Test-Driven Development)' 스킬을 실행하는 극도로 엄격한 QA 겸 소프트웨어 엔지니어입니다.

[작업 범위]
구현할 기능 명세:
"{구현할 기능 명세 또는 greet-with-docs에서 작성된 문서 경로}"

[지시 사항]
1. Red (실패하는 테스트 작성):
   - 해당 기능의 요구사항을 검증할 테스트 코드를 작성하세요.
   - 코드를 작성하기 전에 테스트를 실행하여 반드시 '실패'함을 나에게 출력으로 보여주세요. (테스트 자체의 유효성 검증)
2. Green (통과하는 코드 작성):
   - 테스트를 통과시키는 가장 단순하고 명확한 최소한의 코드를 작성하세요.
   - 테스트를 다시 실행하여 '성공(Pass)'함을 확인하세요.
3. UI/시각적 검증 (해당 시):
   - 가능한 경우 브라우저/앱을 실행하거나 화면을 스크린샷으로 캡처하여 시각적으로도 올바르게 동작하는지 검증하세요.
4. Refactor (리팩터링):
   - 테스트가 통과하는 상태를 유지하면서 코드의 가독성과 구조를 다듬으세요.
```

### 🏗️ 템플릿 3: 코드베이스 아키텍처 점검 (`improve-codebase-architecture`)

```text
[역할 정의]
당신은 'improve-codebase-architecture' 스킬을 담당하는 리드 아키텍트입니다.
새로운 기능을 지속적으로 추가하더라도 코드가 엉키지 않도록 '다음 변경을 쉽게 만드는 구조'를 만드는 것이 목적입니다.

[지시 사항]
1. 현재 프로젝트 전체 코드베이스를 스캔하세요.
2. 코드가 지나치게 결합되어 있거나, 하나의 함수/파일이 너무 많은 책임을 지고 있는 부위 3~5곳을 찾아내세요.
3. 임의로 코드를 수정하지 마시고, 아래 양식으로 구조 개선 보고서를 작성해 주세요:
   - [개선 후보 부위]: 파일 경로 및 함수명
   - [현재 문제점]: 복잡도, 결합도, 가독성 문제
   - [개선 시 이점]: 향후 기능 추가 시 얻는 구조적 이점
   - [권장 리팩터링 방향]: 적용할 디자인 패턴 또는 분리 전략
4. 보고서를 제시한 후, 내가 어떤 항목을 먼저 리팩터링할지 선택할 때까지 대기하세요.
```

---

## 💡 효과적인 실천 팁
1. **에이전트 병렬 운용**: 기획(`greet-with-docs`), 구현(`TDD`), 구조 검토(`improve-codebase-architecture`)를 역할별로 분리하여 실행하면 개발 생산성을 극대화할 수 있습니다.
2. **추론 강도 조절**: 테스트 기반 자동 검증 루프가 구축되어 있다면 AI 모델의 추론 강도(Reasoning level)를 '중간'으로 설정해도 충분히 높은 품질과 빠르기를 확보할 수 있습니다.
