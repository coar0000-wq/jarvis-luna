# 스페이스엑스(SpaceX) 상시 작동(Always-On) 에이전트 아키텍처 및 최적화 가이드

## 1. 개요 및 패러다임의 변화
- **터미널 하네스에서 상시 작동 에이전트로의 전환**: 기존의 개발자 노트북 터미널 기반 스크립트를 넘어, 클라우드 리눅스 서버 환경에서 24시간 365일 상시 작동(Always-On)하는 지속성(Proactive & Persistent) 에이전트로 발전하고 있습니다.
- **동료(Colleague) 형태의 상호작용**: 매번 즉각 대화로 응답하기보다는 필요한 동안 백그라운드에서 작업하며, 중요한 상태 변경이나 업데이트가 있을 때만 사용자에게 알립니다.
- **장기 과제 수행**: 사용자 직접 프롬프트뿐만 아니라 슬랙(Slack), 이메일, 정기 루틴(Routine) 등 다양한 외부 이벤트에 따라 자동으로 깨어나 수 시간에서 수개월에 이르는 장기 과제를 수행합니다.

---

## 2. 핵심 아키텍처 및 시스템 구성

### 2.1. Thin Client & Thick Server 구조
- **단일 통신 인터페이스 (`send_user`)**: 모바일, 데스크톱, 슬랙, 이메일 등 어떤 클라이언트 환경에서든 서버와 통신하는 툴을 `send_user` 단 하나로 단순화했습니다.
- **서버 중심 로직 및 상태 관리**: 에이전트 실행 루프와 대화 기록, 무거운 연산(음성 변환, 이미지 생성 등)을 서버에서 처리합니다. 이를 통해 클라이언트 앱 업데이트 없이 서버 코드를 신속히 배포할 수 있으며, 가상 머신(VM) 재부팅이나 패치 작업 시에도 에이전트 상태가 보존됩니다.

### 2.2. Firecracker VM 기반의 전용 컴퓨터 (Computer Use)
- **격리된 가상 머신 환경**: 에이전트마다 독립된 Firecracker 가상 머신(VM) 기반 리눅스 환경을 할당하여 파일 시스템, 크롬 브라우저, 가상 데스크톱을 운용합니다.
- **수면 및 복원 (Sleep & Wake)**: 자원 및 비용 절감을 위해 작업이 없을 때는 VM 및 서버 상태를 스냅샷으로 저장한 뒤 수면 상태로 전환하며, 이벤트 발생 시 즉시 깨어나 이전 상태를 복원합니다.
- **다단계 자동화 (Computer Use)**: API나 MCP 서버가 없는 서비스라도 브라우저 접근성 트리(Accessibility Tree), HTML, 스크린샷, 실제 좌표 클릭(Computer Use)을 활용해 조작합니다.

### 2.3. Temporal 기반의 내구성 있는 워크플로우 (Durable Workflow)
- **실패 지점 복구**: 일반적인 작업 큐(Job Queue)는 실행 중 크래시가 나면 처음부터 재실행해야 하지만, 오픈소스 인프라 `Temporal`을 적용하여 크래시 발생 시 중단된 단계부터 즉시 재개할 수 있는 내구성을 확보했습니다.

### 2.4. 메인 에이전트와 서브 에이전트(Sub-agents) 분리
- **컨텍스트 오염 방지**: 메인 에이전트(Orchestrator)는 대화 맥락과 전체 할 일 목록(To-Do List)만 가볍게 관리합니다.
- **작업 위임**: 쉘 명령어 실행, 대용량 파일 탐색, 시각 검증 등 토큰 소모가 큰 작업은 새로운 워킹 메모리를 가진 서브 에이전트(Helpers)에게 위임합니다. 서브 에이전트의 작업 결과만 메인 에이전트에 보고하여 무한에 가까운 컨텍스트 체감을 제공합니다.

## 3. 비용 및 컨텍스트 최적화 기법

### 3.1. 동적 툴 발견 (Dynamic Tool Discovery)
- **스키마 온디맨드 로딩**: 수많은 MCP 서버나 외부 API 연동 시 툴 스키마가 프롬프트를 점유하는 문제를 방지하기 위해, 매 메시지에는 '툴 이름 목록'만 최소한으로 포함시킵니다.
- **파일 시스템 기반 탐색**: 에이전트가 특정 툴을 사용하기로 결정하면 파일 시스템에서 해당 툴의 상세 스키마를 동적으로 읽어와 실행합니다.

### 3.2. 프롬프트 캐싱 및 순서 고정 (Prompt Caching & Fixed Order)
- **캐시 미스 방지**: 시스템 프롬프트, 툴 정의 등 정적 요소를 상단에 배치하고 순서를 엄격하게 고정하여 프롬프트 캐싱 할인을 극대화합니다.
- **캐시 웜업**: 사용자가 입력창에 타이핑을 시작하는 시점에 서버가 프롬프트를 미리 준비하여 캐시를 따뜻하게 유지합니다.

### 3.3. 비용 최적화 사다리 (Cost-Effective Fallback Hierarchy)
1. 기존 대화 맥락 내 정보 활용
2. 연동된 API / MCP 서버 / 플러그인 호출
3. 웹 검색 수행
4. 브라우저 및 가상 데스크톱 조작 (Computer Use)
5. 최후의 수단으로 사용자 승인 및 질문 요청

### 3.4. 웜 캐시 타임 컴팩션 (Warm Cache Background Compaction)
- Warm Cache 유효 시간(10~60분) 동안 백그라운드에서 대화 요약(Compaction)을 선제적으로 처리하여, 사용자가 돌아왔을 때 가볍고 저렴한 컨텍스트 상태에서 대화를 이어가도록 합니다.

### 3.5. 계층형 메모리 구조
- **핵심 사실 (Core Facts)**: 유저 맞춤형 핵심 지침 및 설정 (상시 유지)
- **날짜별 기록 (Dated Logs)**: 과거 대화 및 작업 이력 파일
- **임시 메모리 (Ephemeral Scratchpad)**: 현재 세션 단기 정보
- **파일 시스템**: 쉘 명령어(`grep` 등)로 검색 가능한 대용량 문서 저장소

---

## 4. 안전성 및 보안
- **자동 리뷰 (Auto-Review)**: 에이전트가 실행하는 수백 개의 쉘 명령어의 안전성을 별도의 AI 모델이 정밀 검증하여 사용자의 승인 피로를 줄이고 보안을 극대화합니다.
- **프롬프트 인젝션 방지**: 외부 수신 이메일이나 웹훅 등 비신뢰 입력이 사용자 명령어처럼 실행되지 않도록 격리 처리합니다.
