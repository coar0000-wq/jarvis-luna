# 깃허브 스타 29만 개, 맷 포콕의 고품질 AI 코딩 스킬 및 워크플로우 가이드

본 문서는 깃허브 스타 29만 개를 기록한 AI 코딩 스킬 모음의 제작자 맷 포콕(Matt Pocock)이 실제 개발에서 사용하는 고품질 AI 코딩 스킬과 워크플로우를 정리한 종합 가이드입니다 [1].

---

## 1. 개요 및 스펙 주도 개발(SDD)의 한계

* **배경**: 맷 포콕은 100만 구독자의 AI 유튜버 네이트 허크의 채널에 출연하여 실제 AI 기반 개발 노하우를 공개했습니다 [1].
* **스펙 주도 개발(SDD)의 경험**: 상세한 명세서를 작성하고 AI에게 구현을 통째로 맡기는 '스펙 주도 개발(SDD)'을 몇 달간 시도하였으나, 개발이 진행될수록 코드와 AI 출력이 점차 악화되는 문제를 경험했습니다 [1].
* **핵심 문제 원인**: 명세서에만 집중하는 동안 실제 코드 구조가 얽히고 복잡해지는 아키텍처 저하 문제를 해결하지 못했기 때문입니다 [2].

---

## 2. 핵심 AI 코딩 스킬 3가지

### 2.1. 내 의도와 AI의 이해를 일치시키는 스킬: `greet-me` & `greet-with-docs`
* **개발자와 AI 사이의 간극 축소**: 모델 성능이 아무리 발전하더라도 개발자의 마음과 언어화되지 않은 암묵적 조건을 독심술처럼 읽을 수는 없습니다 [1].
* **작동 방식**:
  * **`greet-me`**: 원하는 아이디어나 구현할 내용을 적고 실행하면, AI가 질문을 던지며 누락된 조건과 모호한 부분을 사전에 채워나갑니다 [1].
  * **`greet-with-docs`**: 코딩 프로젝트 전용 스킬로, 기존 코드를 분석하면서 역질문을 통해 결정된 내용을 문서로 기록합니다 [1].
* **용어집(Glossary) 및 의사결정 기록**:
  * 예: 개발자가 말한 '취소'가 단일 상품 삭제인지, 주문 전체 취소인지와 같은 용어 정의의 차이를 명확히 기록합니다 [1].
  * 주요 의사결정 이유까지 기록하여 매번 길게 설명하지 않아도 AI가 동일한 기준과 용어로 작업할 수 있도록 보장합니다 [1].

### 2.2. 자율 검증 및 시각적 확인 스킬: `TDD` (테스트 주도 개발)
* **AI의 자체 동작 검증**: AI가 "완료되었다"고 주장할 때 실제로 기능이 올바르게 동작하는지 테스트 결과로 즉시 확인합니다 [1, 2].
* **의도적 실패 단계 (Red-Green Refactoring)**:
  * 원하는 동작을 검사하는 테스트를 먼저 작성하고, 기능 구현 전 일부러 실패하는 것을 먼저 확인합니다 [1].
  * 테스트가 유효하게 문제를 잡아내는지 사전 검증한 후, 테스트를 통과할 때까지 코드를 반복적으로 수정합니다 [1, 2].
* **시각적 검증 (Visual Inspection)**:
  * 맷 포콕은 영상 편집기 등 실제 UI 애플리케이션을 AI가 직접 실행하고, 링크를 클릭하며 화면을 캡처해 검증하는 환경을 구축했습니다 [2].
  * 이러한 자동 검증 환경이 결합되면서 생성된 결과물의 품질이 크게 향상되었습니다 [2].
* **추론 강도 조절**: 강력한 자율 검증 환경이 구축되면, AI 추론 강도를 최고 단계가 아닌 '중간' 단계로 설정해도 우수한 성능과 효율을 얻을 수 있습니다 [2].

### 2.3. 코드 구조 악화 방지 스킬: `improve-codebase-architecture`
* **아키텍처 저하 방지**: 기능이 추가될수록 코드가 얽혀 하나를 고쳤을 때 다른 곳이 망가지는 현상을 방지합니다 [2].
* **작동 방식**:
  * AI가 전체 코드를 살펴보고 구조 개선이 필요한 후보와 이유를 정리한 보고서를 제시합니다 [2].
  * AI가 임의로 코드를 수정하지 않고, 개발자가 후보를 선택하면 질의응답을 거쳐 안전한 리팩터링 방향을 정합니다 [2].
* **권장 실행 주기**: 며칠에 한 번씩 주기적으로 실행하여 향후 기능 추가가 용이한 유연한 코드베이스 상태를 유지합니다 [2].

## 3. 권장 개발 워크플로우 및 스킬 설정방법

### 3.1. 단계별 표준 워크플로우
1. **기획 및 명세화 (`greet-with-docs`)**: 추가/수정할 기능을 작성하고 AI의 질문에 답하며 구체적인 개발 계획과 용어집을 문서화합니다 [1, 2].
2. **구현 및 검증 (`TDD` & 시각적 검증)**: 실패하는 테스트 작성 -> 코드 구현 -> 테스트 통과 및 시각적 화면 캡처 확인의 과정을 거쳐 기능을 완성합니다 [1, 2].
3. **지속적 리팩터링 (`improve-codebase-architecture`)**: 코드가 복잡해졌거나 주기적인 검토 시점에 아키텍처 개선 포인트를 찾아 수정하기 쉬운 구조를 유지합니다 [2].

### 3.2. 생산성 수치 및 설정 방법
* **생산성 변화**: 자동 검증 및 멀티 에이전트 환경 구축을 통해 4개의 에이전트를 동시에 운용하며, 하루 커밋 수를 과거 20여 개 수준에서 200~300개로 대폭 향상시켰습니다 [2].
* **설정 명령어**:
  * 클로드 코드(Claude Code)에서 명령 한 줄, 코덱스(Codex)에서 두 줄로 스킬 설치가 가능합니다 [2].
  * 작업 대상 저장소에서 `setup-pocock-skills` 명령을 실행하여 프로젝트 할 일과 문서 저장 위치를 자동으로 정립할 수 있습니다 [2].
