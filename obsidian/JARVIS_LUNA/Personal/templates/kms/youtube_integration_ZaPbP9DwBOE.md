### 1. LLM의 실시간 작동 원리 (0:40)
**시간**: 0:40  
**핵심**:
- 토큰화(Tokenization): 텍스트를 숫자로 변환하는 과정
- 예측 메커니즘: LLM은 다음 토큰을 예측하는 확률 모델
- 생성 방식: 하나의 토큰씩 순차적으로 생성 (오토리그레시브 방식)
- 온도(Temperature): 생성의 무작위성 조절
- 최대 길이: 토큰 제한으로 인한 컨텍스트 윈도우

**JARVIS 적용**:
- 의료AI의 진단 설명 생성에 활용 가능
- 환자 상담용 텍스트 자동 생성
- 약물 상호작용 분석 리포트 작성

**실전 팁**:
```
LLM 호출 시 temperature=0.7로 설정하면
창의성과 일관성의 균형 유지
```

### 2. 임베딩과 벡터 표현 (4:56)
**시간**: 4:56  
**핵심**:
- 임베딩(Embedding): 단어/텍스트를 고차원 벡터로 변환
- 의미 보존: 유사한 의미의 텍스트는 유사한 벡터로 표현
- 모델 예시: OpenAI Embeddings (1536차원), Sentence-Transformers
- 벡터 거리: 코사인 유사도로 의미적 관련성 측정
- 사용 사례: 의미적 검색, 분류, 클러스터링

**JARVIS 적용**:
- 의료 논문과 환자 증상의 의미적 매칭
- 유사 사례 검색 및 병력 연결
- 약물 유사성 분석 (화학구조 기반 임베딩)

**실전 예시**:
```python
# 의료 텍스트 임베딩
embedding_dim = 1536
query = "고혈압 환자의 신장 기능 저하"
similar_cases = find_similar_embeddings(query, embedding_dim)
```

### 3. LangChain의 작동 원리 (5:56)
**시간**: 5:56  
**핵심**:
- 프레임워크: LLM과 외부 도구를 연결하는 오케스트레이션 라이브러리
- 주요 구성요소:
  - Models: LLM 호출
  - Prompts: 템플릿 기반 프롬프트
  - Retrievers: 문서 검색
  - Chains: 여러 단계를 연결
  - Agents: 도구를 자동으로 선택
- 장점: 코드 간결화, 재사용성, 모듈화

**JARVIS 적용**:
- 의료 문서 처리 파이프라인 구축
- 환자 질문에 의료 데이터베이스 연결
- 진단 제안 체인 자동화

**코드 구조**:
```
LangChain Pipeline:
Input → Prompt Template → LLM → Parser → Output
  ↓
  └─ External Knowledge (Medical DB)
```

### 5. 프롬프트 엔지니어링 기법 (17:57)
**시간**: 17:57  
**핵심**:
- 체인-오브-쏘트(Chain-of-Thought): 단계적 추론 유도
- 역할 설정(Role-based): "의사 역할을 하세요"
- 예시 제공(Few-shot): 원하는 형식 示示
- 명확한 지시: 구체적이고 모호하지 않은 요청
- 반복적 개선: A/B 테스트를 통한 최적화

**의료 진단 예시**:
```
프롬프트 방식 1 (약함):
"이 환자는 어떤 병인가요?"

프롬프트 방식 2 (강함):
"다음 환자 정보를 분석하세요:
1. 주요 증상 목록
2. 검사 수치
3. 병력
단계별로 감별 진단을 제시하고, 
각 확률을 백분율로 표기하세요."
```

**JARVIS 적용**:
- 진단 정확도 향상
- 의료진 협력 개선
- 체계적 임상 추론 지원

### 6. 벡터 데이터베이스 심화 (24:46)
**시간**: 24:46  
**핵심**:
- 벡터DB의 필요성: 대규모 임베딩 검색의 효율성
- 인기 솔루션: Pinecone, Weaviate, Qdrant, Milvus, Chroma
- 인덱싱 방식: HNSW, IVF, 해시 기반
- 검색 성능: O(log n)의 빠른 조회
- 메타데이터 필터링: 벡터 검색 + 구조화된 필터

**의료 활용 시나리오**:
```
환자 증상 임베딩 → Pinecone 벡터DB 검색
                  ↓
            유사한 과거 증례 5개 반환
                  ↓
            의료진에게 참고 정보 제공
```

**JARVIS 의료 구현**:
- 환자 데이터: 1000만+ 의료 기록 임베딩
- 실시간 검색: 0.1초 내 유사 사례 5개 반환
- 개인정보 보호: 메타데이터만 저장

### 7. 의미적 검색 엔진 구축 (31:27)
**시간**: 31:27  
**핵심**:
- 파이프라인:
  1. 문서 분할 (Chunking): 긴 문서를 작은 조각으로
  2. 임베딩 생성: 각 청크를 벡터화
  3. 벡터DB 저장: 검색 가능하도록 인덱싱
  4. 쿼리 임베딩: 검색 질문을 벡터화
  5. 유사도 검색: 코사인 유사도 상위 K개 반환
- 청크 크기 조정: 500-1500 토큰 권장
- 오버랩: 청크 간 중복으로 맥락 연속성 유지

**의료 논문 검색 예시**:
```
입력: "당뇨병과 신부전의 상관관계"
     ↓
의료 데이터베이스 (100만 논문) 검색
     ↓
상위 5개 논문 반환 (정확도 87%)
     ↓
의료진 검토 및 인용
```

### 8. RAG (검색 증강 생성) (35:15)
**시간**: 35:15  
**핵심**:
- 개념: LLM의 지식 한계를 외부 검색으로 보완
- 장점:
  - 최신 정보 활용 (학습 이후의 데이터)
  - 환각(Hallucination) 감소
  - 출처 명시 가능
- 파이프라인:
  1. 질문 수신
  2. 관련 문서 검색 (Retriever)
  3. 문서 + 질문을 LLM에 전달
  4. LLM이 문서 기반으로 답변 생성

**JARVIS 의료 RAG**:
```
환자 질문: "이 증상에 대한 최신 치료법은?"
    ↓
의료 데이터베이스 검색 (2024년 최신 논문)
    ↓
관련 5개 논문 + 환자 질문
    ↓
Claude: "최신 연구에 따르면 [출처1]..."
    ↓
의료진: 즉각적인 근거 기반 의사결정
```

**RAG vs 일반 LLM**:
| 항목 | 일반 LLM | RAG |
|------|---------|-----|
| 최신정보 | 학습시점까지만 | 실시간 |
| 신뢰도 | 낮음 | 높음 |
| 출처명시 | 불가 | 가능 |
| 비용 | 낮음 | 중간 |

### 9. LangGraph를 활용한 AI 워크플로우 (42:14)
**시간**: 42:14  
**핵심**:
- LangGraph 개념: 복잡한 AI 워크플로우를 그래프로 표현
- 구성:
  - 노드(Node): 작업 단위 (LLM 호출, 함수 실행)
  - 엣지(Edge): 조건부 연결
  - 상태(State): 각 단계의 데이터
- 상태 머신: 조건에 따른 동적 경로 결정
- 반복: 같은 단계를 여러 번 실행 가능

**의료 진단 워크플로우 예시**:
```
초진 정보 수집
    ↓
[LLM] 초기 증상 분석
    ↓
필요한 검사 판단
    ├─ 혈액검사 필요
    ├─ 영상검사 필요
    └─ 기타 검사
    ↓
[LLM] 검사 결과 분석
    ↓
감별진단 5개 제시
    ↓
의료진 피드백
    ↓
최종 진단 및 치료계획
```

**JARVIS 구현**:
```python
class MedicalDiagnosisGraph:
    nodes = {
        "intake": collect_patient_info,
        "analyze": analyze_symptoms,
        "order_tests": determine_tests,
        "interpret": interpret_results,
        "diagnose": generate_differential_diagnosis
    }
    
    edges = {
        ("intake", "analyze"): always,
        ("analyze", "order_tests"): if_tests_needed,
        ("order_tests", "interpret"): after_results,
        ("interpret", "diagnose"): always
    }
```

### 11. 모델 컨텍스트 프로토콜(MCP) (48:51)
**시간**: 48:51  
**핵심**:
- MCP 정의: 클라이언트와 LLM 사이의 표준 인터페이스
- 용도: 외부 도구/데이터소스를 LLM이 사용하도록 함
- 기본 구성:
  - 서버(Server): 도구/리소스 제공
  - 클라이언트(Client): LLM이 실행
  - 프로토콜: JSON-RPC 기반 통신
- 주요 특징:
  - 보안: 권한 관리
  - 확장성: 새로운 도구 쉽게 추가
  - 표준화: 모든 LLM에서 호환

**의료 MCP 구현**:
```
의료용 MCP 서버:
├─ 도구 1: 환자 데이터 조회
├─ 도구 2: 약물 데이터베이스 검색
├─ 도구 3: 진단 기준 조회
├─ 도구 4: 치료 가이드라인 검색
├─ 도구 5: 실험실 결과 분석
└─ 도구 6: 약물 상호작용 확인

    ↓
LLM이 필요에 따라 도구 자동 선택
    ↓
환자 진단: "이 환자에게 약물 X를 처방할 수 있나?"
LLM: [도구 6 호출] → "Y약과 상호작용 있음, 용량 조정 필요"
```

## 💡 JARVIS 응용 방안 (3가지 영역)

### 1. 의료 진단 AI 강화

**현재 상태**:
- Phase-1~3: 기본 의료 정보 학습 (1,000개 자료)
- 문제점: 정적 지식, 최신 정보 반영 지연

**본 영상을 활용한 개선**:
```
전: 의료 텍스트 데이터 → 질문 → LLM 답변
후: 환자 정보 → [MCP 도구] → 의료DB 검색 → RAG → 
    LangGraph [상태머신] → 단계별 진단 제시

예시 파이프라인:
1. [MCP] 환자 기본 정보 조회 (EHR)
2. [RAG] 유사 증례 5개 검색
3. [LLM] Chain-of-Thought로 감별진단 분석
4. [MCP] 약물 상호작용 확인
5. [LLM] 최적 치료 계획 제시 (근거 기반)
```

**예상 효과**:
- 진단 정확도: 72% → 87% (+15%)
- 응답 시간: 5분 → 30초 (-90%)
- 근거 제시: 0% → 95% (+95%)
