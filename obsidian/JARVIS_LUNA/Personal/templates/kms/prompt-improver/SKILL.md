# Prompt Improver

사용자의 모호한 요청을 구체적인 프롬프트로 개선하고, 개선된 프롬프트를 즉시 실행해 결과까지 전달하는 스킬. 좋은 프롬프트의 핵심은 말투·타깃·형식·분량·관점을 구체적으로 지정하는 것이다.

## 작동 순서

1. **요청 분석** — 사용자의 요청에서 빠진 요소를 찾는다: 타깃(누구를 위한 것인지), 형식(글·표·리스트·릴스 등), 분량, 말투/톤, 목적(CTA·설득·학습 등), 관점.
2. **짧게 질문** — 결과가 크게 달라질 핵심 요소가 1~2개 비어 있으면, AskUserQuestion(가능하면)으로 그것만 짧게 묻는다. 3개 이상 묻지 않는다. 합리적 기본값이 있으면 묻지 말고 기본값을 택한 뒤 결과에서 한 줄로 언급한다.
3. **프롬프트 개선** — 아래 개선 패턴을 적용해 요청을 구체적인 프롬프트로 다시 쓴다.
4. **보여주고 바로 실행** — 개선된 프롬프트를 인용 블록으로 짧게 보여준 뒤, 확인을 기다리지 말고 그 프롬프트를 즉시 실행해 결과를 전달한다.
5. **마무리** — 결과 끝에 "조정하고 싶은 부분 있으면 말씀해주세요" 정도로 한 줄만 덧붙인다.

## 개선 패턴

### 글쓰기·콘텐츠 요청

| 모호한 요청 | 개선 방향 |
|---|---|
| AI 티 안 나게 써줘 | 사용자 말투 그대로, 전문용어 없이 |
| 개선해줘 | 개선할 요소를 명시 (예: 진실성, 글의 흐름, CTA) |
| 요약해줘 | 서론 빼고 N줄로 |
| 더 전문적으로 | 독자가 5초 안에 이해하게 명확하게 |
| ~에 대한 글 써줘 | [타깃] 대상으로 첫 줄 후킹부터 |
| 콘텐츠 아이디어 줘 | 훅·유행 포맷 포함 N개 |
| 전체적으로 수정해줘 | 말투 유지, 맞춤법·리듬만 수정 |
| 설득력 있게 | 실제 반론을 반영해서 |
| 캡션 써줘 | 초반 CTA·SEO 키워드 고려, 해시태그 3개만 |

### 질문·학습 요청

| 모호한 요청 | 개선 방향 |
|---|---|
| 설명해줘 | 수치와 구체적 사례로 |
| ~에 대해 알려줘 | 심리·전략·포지션 중심으로 |
| 이게 뭐야? | 뻔하지 않은 관점으로 |
| 어떻게 생각해? | 일반적이지 않은 너만의 답으로 |
| 전략/팁 알려줘 | 개념을 잘게 쪼개서, 또는 반박 형식으로 |
| 예시 보여줘 | 직관적이고 누가 봐도 이해할 예시로 |
| 장점 알려줘 | 아무도 말 못 하는 시선으로 |

## 개선 원칙

- 사용자가 이미 준 정보(말투, 이전 대화의 맥락, 프로젝트 파일)를 최대한 재활용한다. 이미 아는 것을 다시 묻는 것은 최악이다.
- 패턴 표는 예시일 뿐이다. 표에 없는 요청도 같은 원리(타깃·형식·분량·말투·관점 구체화)로 개선한다.
- 개선된 프롬프트는 사용자의 언어로 쓴다 (한국어 요청이면 한국어로).
- 개선 자체를 장황하게 설명하지 않는다. 인용 블록 하나 + 실행 결과가 전부다.

## 출력 형식

```
📝 개선된 프롬프트:
> [개선된 프롬프트 전문]

---
[개선된 프롬프트를 실행한 결과]
```
