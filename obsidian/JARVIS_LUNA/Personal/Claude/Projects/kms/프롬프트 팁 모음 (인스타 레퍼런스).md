## 질문·학습 프롬프트: 이렇게 말하지 마세요 → 이렇게 말하세요

| ❌ 나쁜 프롬프트 | ✅ 좋은 프롬프트 |
|---|---|
| 설명해줘 | 수치와 구체적인 사례를 통해 설명해줘 |
| ~에 대해 알려줘 | ~에 대해 심리, 전략, 포지션을 중심으로 알려줘 |
| 이게 뭐야? | 뻔하지 않은 관점으로 알려줘 |
| ~에 대해 어떻게 생각해 | ~에 대해 일반적이지 않은 너만의 답을 줘 |
| 콘텐츠 아이디어 | 상식 반전 또는 의외성을 활용한 콘텐츠 아이디어를 줘 |
| ~전략 알려줘 | 이 개념을 잘게 쪼개서 설명해줘 |
| ~팁 알려줘 | 이 생각에 반박해봐 |
| 예시 보여줘 | 직관적이고 누가 봐도 이해할 법한 예시 줘 |
| ~장점 알려줘 | 아무도 말 못 하는 시선으로 알려줘 |

## 500+ 프롬프트를 대체하는 Claude 스킬 3개 (Ruben Hassid)

### 1. /how-to
- 간단한 프롬프트를 A→Z 단계별 계획으로 전환
- 필요한 질문을 먼저 물어봄 (AskUserQuestion)
- 처음 해보는 작업에도 적용 가능, "ELI5" 붙이면 쉽게 설명
- 만들기: 스킬 파일 다운로드 → Claude → Customize → Skills → "+" → Create skill → 업로드 → 채팅에서 `/how-to + 원하는 작업`

### 2. /about-me
- 내 컨텍스트(누구인지, 일하는 방식, "좋은 결과"의 기준)를 한 번만 저장
- 매 프롬프트마다 컨텍스트를 다시 입력할 필요 없음
- 호출할 때만 작동 — 항상 켜져 있는 글로벌 설정과 달리 창의성을 죽이지 않음
- 만들기: 기존 about-me 파일을 스킬로 변환해 업로드 → 필요할 때 `/about-me` 호출

### 3. /skill-creator
- 다른 모든 스킬을 만들어주는 스킬
- 인터뷰 후 하나의 스킬 파일로 컴파일
- 팀 전체와 공유 가능 (Customize → Skills → Share)
- 만들기: 아무 채팅에서 `/skill-creator` 입력 후 질문에 답하거나, "make it a skill"이라고 요청

**핵심 원칙: 좋은 프롬프트의 공통점 = 말투/타깃/형식/분량/관점을 구체적으로 지정하는 것**
